**Case title:** Enterprise AI accounting case

**Intro:** I am moving toward business analysis, AI implementation and product-focused technology roles. This independent, AI-assisted portfolio explores how a fictional accounting practice could improve invoice review while keeping human authority and evidence clear. I am developing the independent technical proficiency to explain, modify and troubleshoot the implementation.

**Problem:** Repeated checks, policy lookup and handoffs create review friction. Exceptions and approval need an accountable owner. The case begins with process, requirements and assumptions rather than an unsupported AI promise.

**What exists:** Six independently runnable components connect a consulting playbook to invoice validation, controlled tool proposals, permission-filtered knowledge, evaluation and a restricted Microsoft connector artifact. The default demonstration is deterministic, uses explicit fields and produces local mock effects.

**Evidence:** Published code, release records, hosted checks and historical local integration results can be inspected. A separately recorded genuine local-Qwen test is distinct from fixture planning. Do not present historical results as a current new benchmark.

**Scope:** Synthetic data and business effects; no observed client savings. Live Azure OCR/inference and full Copilot Studio runtime remain unverified. The work used substantial AI assistance; personal mastery is not inferred from the repository.

**Calls to action:** Read the case study → inspect evidence → run the local demo. Use [the canonical case](https://github.com/phlppgdfry/ai-transformation-playbook/blob/main/portfolio/SHOWCASE.md) and [release evidence](https://github.com/phlppgdfry/ai-transformation-playbook/blob/main/portfolio/release-2026-11-01/FINAL-HANDOVER.md). No “Watch video” action until a reviewed file and working URL exist. No invented email, telephone, testimonial or customer logo.

Recommended reading structure: author/direction → business problem → six responsibilities → real screenshots → demonstration and evidence → limitations/AI contribution → existing verified contact navigation. The current integration reuses the existing project-detail layout rather than a new page framework; this copy can guide future owner-approved layout work without being misrepresented as already deployed.
